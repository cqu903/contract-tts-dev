01 · Product overview

这个产品解决什么问题

调用方提交一份完整合同，服务把它变成可拖动、可连续播放、可按段复用的朗读体验。调用方不需要自己切文本，也不需要等整份合同全部生成完。

产品看这里

理解用户体验与边界

上传后马上拿到可用时间轴；第一次播放某段可能需要等待生成，已缓存片段会更快；拖动进度条会从目标片段开头播放。

Java 开发看这里

负责业务系统接入

上传合同、保存 contract_id、处理网关认证和错误码，也可以在业务流程中主动预热重要片段。

前端开发看这里

负责时间轴与播放器

使用 Segment 索引绘制进度条，通过二进制音频接口获取 Blob，管理浏览器预取、连续播放和 Seek。

产品必须知道的四件事

上传成功 ≠ 全文语音已生成上传阶段只保存原文、完成切段并返回时间轴；语音在播放或预热时按段生成。
Segment 是最小播放单元一次只生成一个短片段，失败不会拖垮整份合同；Seek 也会吸附到片段开头。
预计时长用于导航进度条在生成音频前即可使用，但预计秒数不等于引擎最终音频的精确秒数。
语言方案严格隔离同一中文原文选择粤语或普通话，会成为两个不同 Contract，切分、音色和缓存互不混用。
文档怎么读 产品优先阅读“产品说明”和“文本到语音”；开发继续阅读“双语言调用”和“接口参考”。Swagger用于试调接口，原始 Schema 位于 /openapi.json。

02 · Text to speech

从上传文本到播放语音

这条链路分成“上传建索引”和“按需生成音频”两个阶段。这样用户不必等待全文合成，系统也只为真正播放的内容付出算力或云端费用。

1

选择 Template 并上传原文

调用方提交完整合同和 template_id。Template 一次确定合同语言、朗读语言、切分、文字处理与 TTS 配置。

2

生成 Contract 身份并保存原文

后端用“规范 Template ID + 原文”计算 contract_id，原文按内容寻址保存。重复上传相同内容会得到相同 ID。

3

确定性切成 Segment

后端按当前语言规则把合同切成短片段，并对每段计算预计时长。切分结果可重复计算，不额外保存一份加工后的合同。

4

立即返回可用时间轴

上传接口返回 Segment 清单与总预计时长，前端此时就能画进度条和接受 Seek；同时后端在后台预热第 0 段。

5

播放时才准备 TTS 文本

请求某段音频后，后端在合成前一刻处理金额、日期、编号和中英文读法。这个过程只改变送给引擎的文本，不改变合同原文。

6

先查缓存，未命中才合成

相同 Template、最终朗读文本和 Engine Profile 可以复用已有音频；缓存未命中才调用 GPT-SoVITS、CosyVoice 或 Microsoft。

7

返回完整片段并继续预取

后端整段合成成功后返回 WAV 或 MP3。前端播放当前段，同时提前下载后续片段，播放结束后无缝切换。

核心业务对象

对象产品含义关键特性
Contract调用方上传的一份完整合同由原文和 Template 共同确定身份
Template一套完整的朗读方案不是简单语言开关；同时决定切分、读法和引擎配置
Segment一段可独立生成、缓存和播放的朗读单元0-based 下标，是 Seek 和预加载的基本单位
Engine Profile某种语言实际使用的供应商、音色和合成参数变化后自动进入独立缓存空间
Audio Cache已经生成过的片段音频命中时不再访问 TTS，降低等待时间和费用

03 · JavaScript + Java

两种开发语言的完整调用

浏览器前端使用 JavaScript Fetch；Java 业务系统示例使用 Java 17 与 Spring Framework 6.1 的 RestClient。两套示例都覆盖上传、查询索引、获取音频和主动预热。

JavaScript · Browser Fetch
const API_BASE = ""; // 同域部署；跨域时填写网关地址

async function readError(response) {
  try { return (await response.json()).detail; }
  catch { return `HTTP ${response.status}`; }
}

async function uploadContract(text, templateId = "xcash_yue") {
  const response = await fetch(`${API_BASE}/api/contracts`, {
    method: "POST",
    headers: { "Content-Type": "application/json" },
    body: JSON.stringify({ text, template_id: templateId }),
  });
  if (!response.ok) throw new Error(await readError(response));
  return response.json(); // contract_id、template_id、时间轴
}

async function getContractIndex(contractId) {
  const response = await fetch(`${API_BASE}/api/contracts/${contractId}`);
  if (!response.ok) throw new Error(await readError(response));
  return response.json();
}

async function getSegmentAudio(contractId, segIdx) {
  const response = await fetch(
    `${API_BASE}/api/contracts/${contractId}/segments/${segIdx}`,
  );
  if (!response.ok) throw new Error(await readError(response));
  return response.blob(); // audio/wav 或 audio/mpeg
}

async function preloadOnServer(contractId, segIdx) {
  const response = await fetch(
    `${API_BASE}/api/contracts/${contractId}/segments/${segIdx}/preload`,
    { method: "POST" },
  );
  if (!response.ok) throw new Error(await readError(response));
  return response.json(); // cached 或 preloading
}

// 2. 首屏并行请求 0、1、2；只等待第 0 段进入就绪

Java 17 · Spring RestClient
import com.fasterxml.jackson.annotation.JsonProperty;
import java.util.List;
import org.springframework.http.MediaType;
import org.springframework.http.ResponseEntity;
import org.springframework.web.client.RestClient;

public final class ContractTtsClient {
    private final RestClient http;

    public ContractTtsClient(String baseUrl) {
        this.http = RestClient.builder().baseUrl(baseUrl).build();
    }

    public ContractIndex upload(String text, String templateId) {
        return http.post()
            .uri("/api/contracts")
            .contentType(MediaType.APPLICATION_JSON)
            .body(new UploadRequest(text, templateId))
            .retrieve()
            .body(ContractIndex.class);
    }

    public ContractIndex getIndex(String contractId) {
        return http.get()
            .uri("/api/contracts/{id}", contractId)
            .retrieve()
            .body(ContractIndex.class);
    }

    public AudioSegment getAudio(String contractId, int segIdx) {
        ResponseEntity<byte[]> response = http.get()
            .uri("/api/contracts/{id}/segments/{idx}", contractId, segIdx)
            .retrieve()
            .toEntity(byte[].class);
        return new AudioSegment(
            response.getBody(),
            response.getHeaders().getContentType()
        );
    }

    public PreloadResult preload(String contractId, int segIdx) {
        return http.post()
            .uri("/api/contracts/{id}/segments/{idx}/preload", contractId, segIdx)
            .retrieve()
            .body(PreloadResult.class);
    }

    public record UploadRequest(
        String text,
        @JsonProperty("template_id") String templateId
    ) {}

    public record ContractIndex(
        @JsonProperty("contract_id") String contractId,
        @JsonProperty("template_id") String templateId,
        @JsonProperty("total_est_s") double totalEstimatedSeconds,
        List<SegmentMeta> segments
    ) {}

    public record SegmentMeta(
        @JsonProperty("seg_idx") int segmentIndex,
        @JsonProperty("est_dur_s") double estimatedDurationSeconds,
        @JsonProperty("cumulative_start_s") double cumulativeStartSeconds
    ) {}

    public record AudioSegment(byte[] data, MediaType contentType) {}

    public record PreloadResult(String status,
        @JsonProperty("seg_idx") int segmentIndex) {}
}

// 使用示例
ContractTtsClient client = new ContractTtsClient("http://contract-tts:8000");
ContractTtsClient.ContractIndex contract = client.upload(contractText, "xcash_yue");
ContractTtsClient.AudioSegment first = client.getAudio(contract.contractId(), 0);
client.preload(contract.contractId(), 1);
Java 与浏览器的职责不同 Java 服务通常负责认证后的业务编排、保存 contract_id 和主动暖缓存；浏览器负责 Blob 播放、进度条、连续预取和用户交互。不要让浏览器绕过业务网关直接访问生产 TTS 服务。

04 · Integration sequence

Java、前端与 TTS 服务如何协作

推荐由 Java 业务服务位于网关之后管理合同身份；前端获得业务授权后使用同一套 API 或由 Java 服务代理。时间轴立即返回，音频仍按需生成。

业务系统提交合同

Java 服务完成登录态、权限和业务校验后，调用 POST /api/contracts，提交原文与 Template。

TTS 服务保存原文并返回索引

服务完成内容寻址、切段与时长估算，返回 contract_id 和 Segment 时间轴，并在后台预热第 0 段。

前端建立播放器时间轴

前端使用 total_est_s、cumulative_start_s 和 est_dur_s 绘制进度条，此时不需要等待音频。

浏览器获取首段并并行预取

立即请求第 0、1、2 段，只等待第 0 段进入“就绪”；TTS 服务对缓存未命中的片段执行归一化和合成。

连续播放与后续预取

当前段开始播放后，再提前获取后 3 段；收到 ended 事件时直接复用已下载 Blob 并切换下一段。

用户 Seek 时按段跳转

前端把目标秒数映射到 seg_idx，获取目标音频并从段首播放；已经缓存的片段不会再次调用 TTS。

05 · Preloading

预加载策略

系统存在服务端预热和浏览器预取两种机制。两者目的不同，前端接入时不要混为一个接口。

首屏并行请求 3 段

上传成功后，浏览器通过音频 GET 接口同时发起第 0、1、2 段请求；只阻塞等待第 0 段，第 1、2 段留在本地 Promise/Blob 缓冲区。

播放过程中预取后 3 段

开始播放第 N 段后，提前请求 N+1 至 N+3。相同 contract_id + seg_idx 在浏览器内去重，不会重复下载。

三层预加载行为

时机行为是否拿到音频
上传成功时后端后台预热第 0 段否，只写服务端缓存
前端收到索引后GET 第 0、1、2 段是，保存为浏览器 Blob
播放第 N 段时GET 后续最多 3 段是，供连续播放使用
外部系统主动暖缓存POST 指定 Segment 的 preload 接口否，只返回预热状态
POST preload 不是音频下载接口 它只安排后台合成，返回 preloading 不代表音频已经完成。浏览器实际播放仍应调用 Segment 的 GET 接口；如果 GET 与后台预热并发，服务端会按缓存键去重合成。
JavaScript · 浏览器请求去重与向前预取
const audioRequests = new Map();

function loadSegment(contractId, segIdx) {
  const key = `${contractId}:${segIdx}`;
  if (!audioRequests.has(key)) {
    const request = fetch(
      `/api/contracts/${contractId}/segments/${segIdx}`,
    ).then(async (response) => {
      if (!response.ok) throw new Error(`HTTP ${response.status}`);
      return response.blob();
    }).catch((error) => {
      audioRequests.delete(key); // 失败可重试
      throw error;
    });
    audioRequests.set(key, request);
  }
  return audioRequests.get(key);
}

// 首屏：等待 0，同时预取 1、2
const first = loadSegment(contractId, 0);
for (let i = 1; i < Math.min(3, segments.length); i++) {
  loadSegment(contractId, i).catch(console.warn);
}
const firstBlob = await first;

// 播放 N 时：预取 N+1 ... N+3
for (let offset = 1; offset <= 3; offset++) {
  const next = currentSegment + offset;
  if (next < segments.length) {
    loadSegment(contractId, next).catch(console.warn);
  }
}

06 · Endpoint reference

后端接口参考

所有路径均相对于当前服务地址。JSON 错误响应统一包含 detail 字段。

POST

/api/contracts

上传一份完整合同、选择处理 Template，并返回可播放的段索引。原文会按内容寻址落盘，服务端同时安排第 0 段后台预热。

请求 Body · application/json

参数类型必填意义
textstring是合同完整原文。至少包含一个可打印的非空白字符；后端不改写原文。原始空格和换行也参与 contract_id 计算。
template_idstring是选择合同语言、朗读语言、切分规则、归一化规则及 TTS Engine Profile。

Template 可选值

值合同语言朗读语言备注
xcash_yue中文粤语推荐使用的规范 ID
xcash_zh中文普通话独立切分与归一化规则
xcash_en英文英语按英文单词估算时长
xcash中文粤语xcash_yue 的兼容别名；响应返回规范 ID

成功响应 · 200 application/json

Response
{
  "contract_id": "8ddad4...64位sha256...",
  "template_id": "xcash_yue",
  "total_est_s": 31.408,
  "segments": [

      "seg_idx": 0,
      "est_dur_s": 8.108,

响应字段类型意义
contract_idstringsha256(canonical template_id + "|" + 原文)，同一原文和 Template 重复上传会得到同一 ID。
template_idstring规范化后的 Template ID；输入 xcash 时返回 xcash_yue。
total_est_snumber所有 Segment 预计朗读秒数之和，不等于已生成音频的精确时长。
segmentsarray段级时间轴。为了减少 PII 传输，响应不回传每段原文。
seg_idxinteger从 0 开始的 Segment 下标，用于音频与 preload 路径。
est_dur_snumber归一化后朗读文本的预计时长，单位秒。
cumulative_start_snumber该段在合同预计时间轴上的起始秒数。
GET

/api/contracts/{contract_id}

重新读取已上传合同并重建确定性的 Segment 索引。用于刷新页面后的索引恢复或服务间查询。

路径参数类型意义
contract_idstring上传接口返回的合同内容寻址 ID。

成功返回 contract_id、total_est_s 和 segments，字段含义同上传响应；此接口当前不重复返回 template_id。

GET

/api/contracts/{contract_id}/segments/{seg_idx}

获取一个完整 Segment 的音频。缓存命中时直接返回；未命中时等待 TTS 整段合成成功后返回。

路径参数类型意义
contract_idstring上传接口返回的合同 ID。
seg_idxinteger目标 Segment 的 0-based 下标，必须位于 0 ... segments.length - 1。

成功响应 · 200 Binary Audio

Content-Type来源前端处理
audio/wavGPT-SoVITS / CosyVoice使用 response.blob()，不要按 JSON 或文本解析。
audio/mpegMicrosoft Edge / Azure

接口返回完整音频文件，不是边生成边流式响应；同一个缓存键的并发冷请求只合成一次。

POST

/api/contracts/{contract_id}/segments/{seg_idx}/preload

外部调用方可主动预热指定 Segment 的服务端缓存。无需请求 Body。

路径参数类型意义
contract_idstring上传接口返回的合同 ID。
seg_idxinteger准备后台合成的 0-based Segment 下标。

成功响应 · 200 application/json

Response variants
{ "status": "cached", "seg_idx": 2 }
{ "status": "preloading", "seg_idx": 2 }

cached 表示调用时已经命中服务端缓存；preloading 表示任务已安排，但不保证返回时已经合成完成。后台失败只记录服务日志，之后的音频 GET 会重新尝试并返回明确错误。

07 · Playback timeline

播放、进度条与 Seek

预计时间轴在音频生成之前就可用，因此上传成功后可以立即展示并拖动进度条。

JavaScript · 秒数映射到 Segment
function segmentAtSeconds(segments, targetSeconds) {
  for (const segment of segments) {
    const end = segment.cumulative_start_s + segment.est_dur_s;
    if (targetSeconds < end) return segment.seg_idx;
  }
  return Math.max(0, segments.length - 1);
}

const targetSeconds = (rangeValue / 1000) * total_est_s;
const segIdx = segmentAtSeconds(segments, targetSeconds);
const blob = await loadSegment(contract_id, segIdx);

audio.src = URL.createObjectURL(blob);
await audio.play(); // 从目标 Segment 的段首开始
预计时长不是音频精确时长 est_dur_s 用归一化后的文字估算，只用于整份合同的预生成时间轴。实际音频长度会受引擎、音色和语速影响；切段后可使用浏览器音频自身的 currentTime 展示当前段内进度。

08 · Failure semantics

状态码与重试建议

状态码常见原因调用方处理
200请求成功按接口定义解析 JSON 或 Audio Blob。
400Template 未知、原文为空或无法切出可读 Segment修正请求，不要原样自动重试。
404contract_id 不存在/已过期，或 seg_idx 越界必要时重新上传合同并刷新索引。
422缺少 JSON 字段或字段类型错误修正请求 Schema。
500本地 TTS 或服务内部错误可有限次数退避重试，同时记录 detail 供排障。
502TTS 上游拒绝、限流、超时或合成失败指数退避重试；不要自动切换 Provider，以免一份合同混用音色或数据边界。
503Template 已注册，但对应 Engine Profile 未配置停止重试并通知运维检查服务端配置。
Error response
{ "detail": "template profile unavailable: xcash_yue" }

浏览器缓存中的失败 Promise 会被删除，因此下一次播放或 Seek 可以重新请求。建议限制同时预取数量；CosyVoice 等云端服务可能存在较低的并发或 QPM 配额。

09 · Integration boundaries

接入与数据安全边界

认证与资源归属

服务本身不实现登录，也不校验调用方是否拥有某个 contract_id。生产接入必须由上游网关完成认证、访问控制、限流和审计。

保护 contract_id

contract_id 出现在音频 URL 中，应视为敏感标识。避免写入分析平台、公开日志、Referer 或可分享页面。

合同 PII

原文在服务端默认保留 90 天；音频缓存按最近访问时间保留 30 天。部署时应使用受控持久卷并建立备份、删除和访问策略。

云端 TTS 外发

未缓存 Segment 会把归一化后的合同文字发送给选定供应商。正式生产优先使用组织管理的 Azure Speech 资源，不应把 Edge Driver 描述为企业 Azure 接入。
