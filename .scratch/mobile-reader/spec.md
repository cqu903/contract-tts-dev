# Mobile Reader（移動版合同朗讀）

**問題（已由原型回答）：** 對外合同 TTS demo 的移動端（H5 / App WebView）應該是什麼形態？

**原型：** 2026-08-16 用 throwaway UI 原型（`frontend/prototype-mobile.html`，3 個結構性不同變體 `?variant=A|B|C`，接真實 API + 真實音頻）對比了三種形態：

- **A 全屏播放器** — 有聲書式播放器畫面，中央大播放鍵 + 分段刻度進度條
- **B 文稿跟讀（✅ 勝出）** — 合同原文連續文稿 + 跟讀高亮 + 底部 mini-player，點任意條款跳讀
- **C 語音氣泡流** — 每段一條微信式語音氣泡，逐條點播

**Verdict：B。** 理由：合同朗讀的核心訴求是「聽著跟得上紙面條款」——用戶（借款人）要對照正在讀的條款，B 是唯一同屏滿足「聽 + 看 + 跳」的形態；A 聽時看不見條款上下文，C 把條款切碎成氣泡、失去合同的全局感。

**原型歸檔（primary source）：** 分支 `prototype/mobile-ui`（含三變體 + 驗證截圖 + 變體切換器），main 不保留切換器與落選變體。

**已知限制（原型暴露的真問題）：** API 的 index 響應刻意不回傳段文本（PII，ADR-0001），因此 B 的跟讀對齊是**時間/字符比例近似**（實測偏差 1-2 段）。精確對齊需 API 增加每段 char offsets（只回偏移量、不回文本，無 PII 增量）→ 見 issue 02。
