# v1 不做资源归属校验（接受 IDOR 残余风险）

对外服务 v1 **不校验**请求者对 `contract_id` 的归属：`contract_id` 作 bearer 凭证直接出现在音频 URL（`GET /contracts/{contract_id}/segments/{n}`）里，且不做日志脱敏等运维补偿。

**理由**：上游 gateway 已做登录认证，团队判断 `contract_id` 经由日志 / Referer / 分享等渠道泄露给其他已登录用户的概率可接受；v1 以接口最简为先。

**残余风险**：一旦某 `contract_id` 经上述渠道泄露，任何已登录用户均可越权获取该合同的音频（IDOR / BOLA）。内容寻址只能防「凭空构造他人 id」（sha256 抗碰撞），**防不了「id 泄露后越权」**——而 id 因出现在音频 URL 里，会沉淀在浏览器历史、访问日志、Referer 中。

## 考虑并否决的方案

- **contract_id 编码 owner + 取音频校验归属**：无状态，既防构造又防泄露越权，但改 `contract_id` 定义、与 ADR-0001 的纯内容寻址偏离。
- **音频 URL 用短期签名**：无状态、把泄露窗口收窄到几分钟，但前端需先换签名 URL 再播，多一次请求。
- **运维补偿（日志脱敏 / 短留存 / 标注 secret）**：零代码、堵最大泄露渠道，但 v1 选择连此也省。

三者均留待真实越权事件或合规要求触发后再加。
