# 缓存键纳入引擎，消除切换引擎的脏读

音频缓存键从 `sha256(归一化文本 + 音色)` 扩为 `sha256(归一化文本 + 音色 + 引擎)`。

**背景**：引擎由启动环境变量 `SEEK_PROBE_ENGINE` 选定（本地 GPT-SoVITS / 云端 CosyVoice），切换靠重启服务。但磁盘缓存不随重启清除，而旧缓存键（`cache.py` 的 `cache_key`）不含引擎——若不手动清缓存，重启切到新引擎后会命中旧引擎的音频（脏读）。对外服务缓存跨合同复用、体量大，「忘清」概率陡增，脏读会静默发给真实用户。

**决策**：把引擎纳入缓存键。切换引擎后，新请求的键随之改变，自动不再命中旧引擎缓存、重新合成；旧引擎缓存成「孤儿」，由 ADR-0004 的 30 天滑动窗口清理。无需人工 `rm`。

**代价**：换引擎后旧缓存短暂占盘（至 TTL 清理）；缓存键多一个维度（音色与引擎均为服务端常量，对调用方透明）。可接受——换取消除一类脏读 bug。

**修正 ADR-0001**：音频缓存键表述从「归一化文本 + 音色」改为「归一化文本 + 音色 + 引擎」。
