# 缓存键 = 归一化文本 + 引擎（音色是引擎内部固定属性）

音频缓存键 = `sha256(归一化文本 + 引擎)`。音色不是独立的键维度——它是每个引擎内部固定的、经检验合格的属性（本地 GPT-SoVITS 靠 `refs/cantonese_ref_trim.wav` 参考音，云端 CosyVoice 靠 `BAILIAN_VOICE`），对调用方透明、不可外部指定。

**背景**：引擎由启动环境变量 `SEEK_PROBE_ENGINE` 选定（本地 GPT-SoVITS / 云端 CosyVoice），切换靠重启服务。但磁盘缓存不随重启清除，而旧缓存键若不含引擎——重启切到新引擎后会命中旧引擎的音频（脏读）。对外服务缓存跨合同复用、体量大，「忘清」概率陡增，脏读会静默发给真实用户。

**决策（引擎入键）**：把引擎纳入缓存键。切换引擎后，新请求的键随之改变，自动不再命中旧引擎缓存、重新合成；旧引擎缓存成「孤儿」，由 ADR-0004 的 30 天滑动窗口清理。无需人工 `rm`。

**决策（音色不入键）**：v1 每个引擎只用一个固定音色，不需要多音色，因此音色不必作为键的独立维度。这把键压到最简（文本 + 模型），也与「朗读维度由服务全权决定」（ADR-0001）一致。代价是**换音色不再自动失效缓存**——换参考音 / `BAILIAN_VOICE` 后，键不变，旧音色音频会被命中直读，直到 30 天 TTL 清理。处置纪律：换音色是内部发布，须手动 bump `SEEK_PROBE_ENGINE`（如 `gptsovits-v2`）或清空 `cache/`。

**代价**：换引擎后旧缓存短暂占盘（至 TTL 清理）；缓存键仅一个维度（引擎，服务端常量，对调用方透明）。换音色需手动失效（见上）。可接受——换取消除「切引擎脏读」这类 bug，且 v1 无多音色需求。

**修正 ADR-0001**：音频缓存键表述从「归一化文本 + 音色」改为「归一化文本 + 引擎」（音色不再入键）。
